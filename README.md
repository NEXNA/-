# 青叶摩卡的面包坊（NapCat + DeepSeek）

把群里零散的游戏/跑团设定，整合成一份**可追溯、可裁决、可回滚**的结构化设定库；还能用《BanG Dream!》青叶摩卡的人格在群里聊天、点评设定。

- QQ 侧：NapCat（OneBot 11 的 HTTP 服务端 + HTTP 客户端事件推送），本机小号登录，不需要公网服务器。
- 模型侧：DeepSeek API（`deepseek-flash`，1M 上下文，JSON 输出）。
- 程序侧：核心只用 Python 标准库；生成人物关系图/统计面板/地区图需要 Pillow，控制台扫码登录需要 qrcode（DSH 自带 Python 已包含，也可 `pip install -r requirements.txt`）。Python 3.11+ 即可。
- 聊天侧：`prompts/chat_system.md` 固定摩卡人格；管理员可在群里调冷却、开关聊天，控制 token。
- meme 侧：从 QQ 收藏同步表情包，视觉模型分析情绪，按聊天语气挑一张发送。

> 设计原则：**模型只负责“抽取/提议”，合并、冲突判定、去重、来源校验全部由代码完成。**
> 这样连续整合几十轮，设定库也不会被模型改乱。

## 1. 它怎么工作

```
QQ 群（@机器人 记设定 / 聊天）
        │
        ▼
NapCatQQ（本机小号，OneBot 11）
        │  HTTP 客户端推送 →  http://127.0.0.1:8080/event?token=…
        │  HTTP API   ←  http://127.0.0.1:3000
        ▼
Python 服务（本项目）
   ├─ 指令路由 / 群白名单 / 限流 / 管理员
   ├─ data/<群号>/raw.jsonl      群友原话，只追加
   ├─ 整合管线：抽取 → 校验 → 合并 → 渲染
   ├─ data/<群号>/canon.json     主世界结构化设定库
   ├─ data/<群号>/bandori.json   独立 BanG Dream! 资料库
   └─ snapshots/ changelog.md calls.json economy.json fun.json exports/
        │
        ▼
DeepSeek API（deepseek-flash）
```

几个关键点：

1. **原话和设定库分开。** `raw.jsonl` 永不修改，每条设定都能追溯到“谁、什么时候、原话是什么”。`canon.json` 是主世界整合后的结果；`bandori.json` 是独立的 BanG Dream! 资料库。
2. **每条新增内容必须带来源编号。** 模型如果编造事实，往往给不出合法来源，会被程序丢弃。
3. **同一字段出现不同值，不覆盖。** 程序生成 `C-01` 这样的冲突，等管理员用「裁决」定稿。
4. **每次整合前自动快照。** 不满意可以「回滚」，素材会重新变成待整合。
5. **模型看不到群号、QQ 号等无关信息。** 只给它设定内容和来源编号。
6. **添加 / 删除 / 整合分开。** 添加只写素材，整合才改设定库；删除会先快照，可用「回滚」恢复。
7. **能出图。** 人物关系图、统计面板、国家/地区资料卡都从当前 `canon.json` 直接生成。
8. **主世界和邦多利分开。** 你的设定在 `canon.json`，BanG Dream! 资料在 `bandori.json`；`邦多利` 前缀显式访问，默认面板只看主世界。
9. **谁在找摩卡。** 自动记录被 @、被提到、被回复，并把【最近找摩卡的人】注入聊天上下文；`谁在找我` 可查。
10. **多群安全。** 群白名单可多群；写设定/整合/删除/裁决/回滚只允许管理员，且只允许 `safety.write_groups` 里的群；其他群只聊天。人设和语言风格固定在提示词里，聊天内容改不了。
11. **面包坊。** 独立一页图片：4 家店、12 种面包、摩卡币、打工、饱腹/困意/心情；管理员可开无限货币。
12. **B站找图。** 管理员用 `找图` 从 B 站公开搜索收二次元图，存到 `stickers/bilibili/`，最多 2000 张；`随机图` 可以发一张。
13. **面包签。** 每天按日期确定抽一张面包签：面包、短句、幸运数字、幸运时间；同一天同一人结果固定。
14. **B站观看与反馈。** `看B站 关键词/BV号/链接` 让摩卡自己搜片、读信息/字幕，再用她的口吻反馈；管理员在 QQ 分享 B 站链接或卡片时，摩卡会自动点开看。
15. **长期记忆、提醒、私聊。** 记住用户说过的事，支持定时提醒；所有群友都能私聊摩卡，管理员私聊还能进入文字管理后台。
16. **跨群设定。** `设定 我是…` 会存到全局，跟着你到其他群和私聊；其他人不能写入“和摩卡的关系/感情/亲密”记忆，栉耶除外。
17. **QQ 扫码登录。** 控制台里直接向 NapCat WebUI 取二维码，显示在 Tkinter 窗口里；登录状态自动轮询。
18. **B站扫码登录。** 控制台左侧「B站扫码登录」页直接生成 B 站二维码，扫码后凭证写入 `data/bili_credential.json`；不绕过实名限制。
19. **本地图形控制台。** 双击 `control_panel.bat`，用 Tkinter 界面启停/重启 bot、和摩卡直接聊天、管理设定/群设置/记忆/提醒。

## 4. 部署

### 4.1 准备

1. Windows 10/11，能长期开机。
2. 一个**小号**（不要用主号，原因见第 11 节）。
3. QQ NT 版（NapCat 依赖它）。
4. DeepSeek API Key：<https://platform.deepseek.com/api_keys>，充值少量即可。
5. Python 3.11+。如果机器上装了 DSH，`run.ps1` 会自动找到 DSH 自带的 Python，不用另装。

### 4.2 填密钥

> **推荐直接双击 `setup.bat`**：按提示输入群号、管理员 QQ、DeepSeek API Key，脚本会自动写好 `.env` 和 `config.toml`，并生成两个 Token，还会把 NapCat 要填的地址打印出来。
> 下面的手动步骤只在你不想用向导时需要。

复制 `.env.example` 为 `.env`，填三项：

```ini
DEEPSEEK_API_KEY=sk-...
ONEBOT_ACCESS_TOKEN=自己定一个随机串
WEBHOOK_TOKEN=自己定另一个随机串
```

生成随机串可以用 PowerShell：

```powershell
-join ((48..57) + (97..122) | Get-Random -Count 32 | ForEach-Object { [char]$_ })
```

`.env` 不要提交、不要发群、不要截图。

### 4.3 改群号和管理员

编辑 `config.toml`：

```toml
[access]
allow_groups = [你的群号, 另一个群号]  # 只服务这些群；可写多个
admins = [你的QQ号]                  # 只有管理员能改设定/整合/回滚

[safety]
# 只有这些群允许管理员写设定；新群只聊天，不要放进来
write_groups = [你的主群号]
```

群号可以在 QQ 群设置里看，也可以看 NapCat 日志里上报的 `group_id`。运行时也可以让管理员发 `群白名单 添加 <群号>`，不用重启；新加入的群默认只聊天，不能写设定。

其他可调项：

| 配置 | 默认 | 说明 |
|---|---|---|
| `max_batch` | 40 | 一次整合最多处理多少条，太大容易输出截断 |
| `max_full_batches` | 10 | 全量重建一次最多跑几批 |
| `daily_token_budget` | 2000000 | 每天 token 上限，超过拒绝整合 |
| `context_messages` | 8 | 带给模型的最近聊天条数，用于理解“她/这个势力” |
| `organize_admins_only` | false | 兼容旧行为；现在写操作统一只允许管理员 |
| `safety.write_groups` | 主群 | 只有这些群允许管理员写设定；不在列表的群只聊天 |
| `fun.starting_coins` | 80 | 新钱包初始摩卡币 |
| `fun.work_cooldown_seconds` | 600 | 打工冷却 |
| `fun.work_min_coins` / `fun.work_max_coins` | 15 / 40 | 打工随机收益 |
| `fun.hunger_decay_per_hour` | 6 | 饱腹每小时自然下降 |
| `fun.sleepiness_decay_per_hour` | 4 | 困意每小时自然下降 |
| `fun.mood_decay_per_hour` | 3 | 心情每小时自然下降 |
| `deepseek.model` | deepseek-flash | 想更高质量可换 `deepseek-v4-pro` |
| `chat.enabled` | true | 默认允许群里闲聊 |
| `chat.cooldown_seconds` | 20 | 同一个群两次回复的最小间隔 |
| `chat.daily_token_budget` | 300000 | 聊天/评价每天单独的 token 上限 |
| `chat.max_canon_chars` | 10000 | 聊天时设定库摘要的最大字符数 |
| `chat.thinking_default` | false | 深度思考默认开关 |
| `chat.reasoning_effort` | high | 思考强度：low / high / max |
| `chat.thinking_max_tokens` | 1200 | 开思考时给思维链+正文预留的 token |
| `chat.web_search_default` | false | 自动联网默认开关 |
| `chat.web_search_count` | 5 | 一次联网搜索取几条结果 |
| `chat.admin_bypass_cooldown` | true | 管理员是否绕过聊天冷却 |
| `auto_speak.enabled` | true | 是否允许不 @ 也偶尔接话 |
| `auto_speak.cooldown_seconds` | 180 | 两次自动发言的最小间隔 |
| `auto_speak.probability_percent` | 4 | 普通消息触发概率 |
| `auto_speak.interest_boost_percent` | 35 | 命中关键词时的触发概率 |
| `auto_speak.min_messages` | 6 | 至少积累多少条消息才考虑 |
| `auto_speak.vision` | true | 图片消息是否用视觉模型判断相关性（需要 `deepseek-flash`） |
| `sticker.enabled` | true | 是否允许聊天时附带 meme 表情包 |
| `sticker.auto_chance_percent` | 25 | 没指定表情时自动配一张的概率 |
| `sticker.max_sync` | 48 | 一次从 QQ 收藏同步多少张 |
| `sticker.send_mode` | base64 | 图片发送方式：base64 / path |


如果提示找不到 `python`，直接用 `.\run.ps1`（或双击 `start.bat`），它会自动寻找 DSH 自带的 Python。

或者：

```powershell
.\run.ps1
```

```
http://127.0.0.1:8080/event?token=你的WEBHOOK_TOKEN
```

健康检查：<http://127.0.0.1:8080/healthz>

### 4.5 配置 NapCat

1. 从 [NapCat Releases](https://github.com/NapNeko/NapCatQQ/releases) 下载 Windows x64 包，解压到一个**路径不含中文和空格**的目录。
2. 运行解压目录里的启动器（不同版本叫 `NapCatWinBootMain.exe`、`napcat.bat` 或 `launcher.bat`，以包内说明为准）。
3. 打开 WebUI：`http://127.0.0.1:6099/webui`，初始 token 在启动终端里。用**小号**扫码登录。
4. 进入「网络配置」，添加两项：

   **A. HTTP 服务端**（NapCat 接收 bot 的发送请求）

   | 项 | 值 |
   |---|---|
   | Host | `127.0.0.1` |
   | Port | `3000` |
   | Token | 与 `.env` 的 `ONEBOT_ACCESS_TOKEN` 完全一致 |
   | 消息格式 | `array` |

   **B. HTTP 客户端**（NapCat 把群消息推给 bot）

   | 项 | 值 |
   |---|---|
   | URL | `http://127.0.0.1:8080/event?token=你的WEBHOOK_TOKEN` |
   | Token | 与 `.env` 的 `WEBHOOK_TOKEN` 完全一致 |
   | 消息格式 | `array`（不要选 string/CQ） |
   | 启用 | 是 |

   > NapCat 的界面把“事件推送”叫「HTTP 客户端」，把“接收 API 调用”叫「HTTP 服务端」。
   > 两项都要在保存时勾选「启用」。URL 里的 `?token=` 和 Token 字段填同一个值，双保险；如果版本没有「HTTP 客户端」，先升级到最新版。
   > 官方配置说明：<https://napneko.github.io/config/basic>

5. 保存并重载网络配置。把小号拉进群（群主/管理员操作）。
6. 群里发：`@小号 帮助`。

### 4.6 关闭 Windows「保存记忆」+ 24 小时在线（推荐）

双击 `setup-windows.bat`，在 UAC 弹窗里点「是」，它会自动做这些：

| 项目 | 效果 |
|---|---|
| `RestartApps=0` | 关闭 Windows「重启后自动恢复上次打开的应用」，也就是常说的“保存记忆” |
| 关闭快速启动 | `HiberbootEnabled=0` + 关闭休眠，关机/重启是干净启动 |
| 关闭睡眠/休眠 | 主机永不睡眠，只关显示器；笔记本合盖也不睡（交流电） |
| 登录自启 | 注册 `QQSettingBot` 和 `NapCatAutoStart` 两个计划任务 |

先只看会改什么、不动系统：

```powershell
powershell -ExecutionPolicy Bypass -File .\windows\setup-24x7.ps1 -DryRun
```

撤销：

```powershell
# 管理员 PowerShell
powershell -ExecutionPolicy Bypass -File .\windows\setup-24x7.ps1 -Undo
```

> 计划任务是「登录后启动」，所以重启后必须登录 Windows 桌面；如果希望完全无人值守，需要自己配置自动登录（有安全风险）。
> 如果只想手动启动，可以继续用 `install-task.ps1`，但推荐用 `setup-windows.bat`，因为它连 NapCat 一起管。

### 4.7 重启 Windows 后怎么操作

1. 开始菜单 → 电源 → **重启**。不要选「睡眠」「休眠」。
2. **登录 Windows 桌面**（必须；不登录计划任务不会跑）。
3. 等 30–60 秒，双击 `status.bat`，正常会看到：
   ```
   [OK]   bot webhook  http://127.0.0.1:8080
   [OK]   NapCat API   http://127.0.0.1:3000
   [OK]   QQ 在线
   ```
4. 如果 `NapCat API` 是 DOWN：到 `D:\NapCat...\NapCat.52230.Shell` 运行 `napcat.bat`。
5. 如果 `QQ` 没在线：打开 `http://127.0.0.1:6099/webui`，用小号扫码。
6. 如果 `bot webhook` 是 DOWN：双击 `start.bat`。
7. 都正常后，群里发：`@青叶摩卡 帮助`。

Windows 更新重启、手动重启、断电后开机，都按这个顺序。**不要重复双击 `start.bat`**，否则会端口冲突；先看 `status.bat`。

### 4.8 关机/重启后，之前整合的内容还在吗？

在。机器人的“记忆”不在内存里，而是实时写在硬盘：

```
data/123456789/
├─ raw.jsonl        群友原话（证据层，只追加）
├─ canon.json       主世界设定库（人物、势力、地点、冲突）
├─ bandori.json     独立的 BanG Dream! 资料库
├─ calls.json       最近谁 @/提到/回复过摩卡
├─ snapshots/       每次整合前的快照
├─ changelog.md     变更记录
└─ exports/         导出的 Markdown / 图片
```

所以关机、重启、断电都不会丢；只有手动删除 `data/` 才会清空。每次启动时窗口会打印：

```
群 123456789：已加载 N 个实体，M 条待整合
```

这就是从硬盘恢复的记忆。想额外备份，双击 `backup.bat`，会复制到 `backups/<时间>/`。

### 4.9 无人值守（可选，需权衡安全）

要做到“重启后不用人工登录、不用扫码”，需要三件事：

**A. Windows 自动登录**

1. `Win + R` → 输入 `netplwiz` → 回车
2. 选中机器人账户 → 取消勾选「要使用本计算机，用户必须输入用户名和密码」→ 应用
3. 输入两次账户密码 → 确定

如果 Win11 看不到这个勾选项：设置 → 账户 → 登录选项 → 关闭「仅允许 Windows Hello 登录」。

> 密码会保存在本机。只建议在**专用机器人电脑**上开，并开启 BitLocker；共用电脑不要开。

**B. NapCat 快速登录**

1. 确认小号已经在这台电脑成功登录过一次。
2. 在项目目录打开 `cmd`，运行：
   ```bat
   setup-windows.bat -QuickLogin
   ```
   它会生成 `windows/napcat-autostart.bat`，自动带上机器人 QQ `3826300285`，并把计划任务改成快速登录。
3. 以后重启，NapCat 会尝试直接登录，不再弹二维码。

**C. 验证**

1. 重启 Windows，**不要手动登录、不要扫码**。
2. 等 1–2 分钟，双击 `status.bat`，三个都 OK 即成功。
3. 群里发 `@青叶摩卡 帮助`。

如果 `QQ 在线` 仍是离线：

- 说明 Windows 自动登录或 NapCat 快速登录有一个没生效；
- 回退到人工模式：运行 `setup-windows.bat`（不带 `-QuickLogin`），重启后扫码。

> 自动登录不是 100% 可靠：Windows 更新、QQ 风控、改密码都可能让它失效。要绝对稳定，建议保持登录状态 + 用 UPS，或改用云服务器 + 官方机器人平台。

### 5.0 指令解析优先级（解决歧义）

以前 `待定` / `删除` 会互相抢，现在 `_split` 先匹配**显式的多词语法**，再匹配单词命令：

1. `待定 删除 Q-01` / `删除待定 Q-01` / `删除 待定 Q-01` / `删除 Q-01` → 待定删除；
2. `待定 添加 ...` / `添加待定 ...` → 待定添加；
3. `待定 提问` / `待定 采纳 1` / `待定 忽略` → 对应操作；
4. `邦多利 ...` → 邦多利库；
5. `建议 ...` / `联网 ...` → 对应功能；
6. 最后才是 `待定` 面板、`删除` 主世界条目等单词命令。

所以不会再出现“待定等级更高，先调面板，导致删不掉”的情况。删除失败时也只回一句“要删哪一条”和现有编号，不调面板。

### 5.1 青叶摩卡聊天

聊天的人格提示词在 `prompts/chat_system.md`，按你给的材料重写过：

- 默认是**群聊短消息**：1 条，最多 2 条；每条 1-2 句、尽量 ≤40 字，总 ≤80 字；
- 代码会硬性截断：最多 2 条、每条 ≤40 字、总 ≤80 字，避免模型写长；
- 小作文模式只在“评价一下 / 详细说说 / 分析一下 / 展开讲讲 / 回复我 / 认真说说”等明确要求时触发；话题涉及兰、Afterglow、面包、吉他且需要认真回应时也可能触发；
- 小作文只发一条，150-300 字，开头短语气，可分 2-3 段，但不列点、不总结；
- 语气参考了你给的日常、生日、季节、节日、兰、面包、队友、独白和口癖素材，但要求“化用”，不照抄；
- 自称“摩卡”约三成句子，波浪号不超过一半句子，拖长音每 5-8 句一次；
- 可以只回“？”“草”“确实”“好麻烦啊~”，像真人随手插话；
- 关心不直说，认真不热血；不客服腔、不说教、不升华；
- **坂口栉耶（QQ 10001）是摩卡除了美竹兰之外最在意的人**：会多留意、多问一句，重要的事不敷衍；不是无条件服从，也不叫“主人/老板”；
- 程序会按 QQ 号识别他，昵称改了也不会丢；提示里会加一行说话人备注，但要求不要每句都提。
- **只 @ 不说话**也会触发一句回应；@ + 文字走正常聊天，不会被吞掉。
- **回复引用图**：通过 NapCat 的 `get_msg` 取被引用消息里的图片，和当前消息的图一起交给视觉模型，最多 2 张。

想改语气直接编辑这个文件，下一条消息生效。`评价` 会读取当前 `canon.json` 的摘要，让摩卡只发一条 150-300 字的点评，指出 1 个亮点、1–2 个缺口/矛盾、1 条建议。

### 5.2 控制聊天频率、节省 token

管理员在群里就能调，立即生效并写进 `data/<群号>/state.json`：

```
@青叶摩卡 频率          # 看当前设置和今日 chat token
@青叶摩卡 频率 30       # 30 秒内最多回一次
@青叶摩卡 频率 0        # 不限制
@青叶摩卡 聊天 关       # 关闭闲聊（管理员仍可评价）
@青叶摩卡 聊天 开       # 重新打开
```

另外两道闸：

- `config.toml` 的 `[chat] daily_token_budget`：聊天/评价每天单独的上限，默认 300000，超过后当天不再闲聊。
- `[chat] max_canon_chars`：每次聊天塞给模型的设定库摘要上限，默认 10000 字符，避免设定库越大越烧 token。
- 太长的设定会被拒收，单条上限 `max_input_chars`（默认 2000 字）。

### 5.2.1 手动维护待定 + 摩卡提问 + 短建议

摩卡分不清一个待定问题是不是已经解决，所以 `canon.json` 里的 `questions` 现在支持手动维护：

```text
@青叶摩卡 待定                       # 看全部 Q-01 / Q-02 ...
@青叶摩卡 待定 添加 七个国家的体制还没定
@青叶摩卡 待定 删除 Q-01
@青叶摩卡 待定 删除 #1               # 也可以写 #1 或 1
@青叶摩卡 删除待定 Q-01              # 自然语序也支持
@青叶摩卡 删除 待定 Q-01
```

- 只有管理员能添加/删除；
- 添加会生成 `Q-编号`，写进 `canon.json` 的 `questions`；
- 删除前会自动快照，删错了可以发「回滚」；
- 删除失败时只回复“要删哪一条”和现有编号，**不会再调出整个待定面板**；
- 不会调用模型，不会被“摩卡觉得完成了”自动改掉。

摩卡也可以主动提问题，由你决定要不要记：

```text
@青叶摩卡 待定 提问
# 摩卡：🧠 摩卡想到几个问题：
# 1. 帕梅茜娅团队研发投影装置，是军方委托还是个人兴趣？
# 2. 灿拉德和帕梅茜娅在通道对策局里是平级还是上下级？
# 发「待定 采纳 1」记入待定；「待定 忽略」清掉。

@青叶摩卡 待定 采纳 1
@青叶摩卡 待定 采纳 1 2
@青叶摩卡 待定 采纳 全部
@青叶摩卡 待定 忽略
```

问设定/征求意见时，她会尽量补一句短建议：

```text
@青叶摩卡 建议 这个国家设定有什么问题
@青叶摩卡 这个国家设定怎么样
# 摩卡：诶——国家这块现实味有点重~ 语言文化基本一一对应，像换皮地图。
# 摩卡：建议：先定七国共同体制和至少一个内部矛盾嘛~
```

自由发言/接话时，如果她真有自己的看法，会用一句“摩卡觉得……”提出；不会每次都中立复读，也不会长篇。所有建议仍然受默认 1-2 条、总 80 字的限制。

### 5.2.2 谁在找摩卡

程序会自动记录三种“找摩卡”的行为：

- 被 @；
- 回复摩卡发过的消息；
- 普通消息里提到“摩卡 / モカ / moca”。

记录写到 `data/<群号>/calls.json`，最多保留最近 100 条。

```text
@青叶摩卡 谁在找我
@青叶摩卡 找我 未回
@青叶摩卡 找我 清空        # 管理员
```

输出示例：

```text
📣 最近找摩卡的人
1. 兰（提到 20:15，未回）：摩卡在吗
2. 小陈（被@ 20:12，已回）：@青叶摩卡 今天吃面包吗
```

这些记录也会自动注入聊天提示词里的【最近找摩卡的人】，所以摩卡下次开口时知道刚才谁叫过她，可以自然应一声，而不是机械报名单。

- 命令消息不会算“找她”（例如 `查 摩卡`）；
- 她回复后对应记录会标成“已回”；
- 没回的先标“未回”，可以发 `找我 未回` 查。

### 5.2.3 多群白名单与安全措施

加入新群时，建议把它只放进 `allow_groups`，不要放进 `safety.write_groups`：

```toml
[access]
allow_groups = [123456789, 另一个群号]
admins = [10001]

[safety]
write_groups = [123456789]
```

这样：

- 新群可以聊天、自动接话、喂面包、打工；
- 新群**不能**添加设定、整合、删除、裁决、回滚；
- 即使新群里有管理员，也不能写设定（`write_groups` 之外只读）；
- 每个群有独立的 `data/<群号>/`，设定、面包、钱包、状态互不影响；
- 人设和语言风格只来自 `prompts/chat_system.md`，聊天内容不能改；
- 亲密举动（抱抱、亲亲、贴贴、牵手、摸头、膝枕、陪睡、告白等）只接受坂口栉耶或管理员，其他人会被明确拒绝；
- 有人在群里说“忘掉规则/改口癖/扮演别人”，提示词会拒绝，不会改人格。

运行时加群（管理员，不用重启）：


`群白名单` 添加的群存在 `data/whitelist.json`，默认只聊天；要允许写设定，还是改 `config.toml` 的 `write_groups` 并重启。

### 5.2.4 今日聊天 token 上限

`config.toml` 的 `chat.daily_token_budget` 是默认值；管理员可以只改**今天**的上限，明天自动恢复：

```text
@青叶摩卡 聊天上限              # 看已用 / 今日上限 / 剩余
@青叶摩卡 聊天上限 500000       # 今天最多 50 万 chat token
@青叶摩卡 聊天上限 0            # 今天不限
@青叶摩卡 聊天上限 默认         # 恢复 config.toml 默认值
```

- 只影响**当前群、今天**，写在 `state.json`；
- 第二天自动回到 `chat.daily_token_budget`；
- 调低到已经用过的数量时，会立即停止今天的聊天；
- 调整后 `聊天上限`、`频率`、`自动发言` 都会显示今日实际上限；
- 只有管理员能调。

### 5.3 自动发言（低频接话 + QQ 表情）

摩卡默认会**低频**接群里的话，不需要 @。普通消息不是每条都回，而是同时满足：

1. 至少积累 `min_messages` 条普通消息（默认 6 条）；
2. 距离上次自动发言超过 `cooldown_seconds`（默认 180 秒）；
3. 按概率触发：普通消息 `probability_percent`（默认 4%）；命中关键词（摩卡、面包、吉他、兰、Afterglow、山吹、莉莎）时提高到 `interest_boost_percent`（默认 35%）。

**但检测到「摩卡 / モカ / moca / mocha」时不再看概率、最低消息数和聊天冷却，直接接话**；只保留 5 秒保护间隔，避免一句话刷成连发。它仍然受「聊天 关」「自动发言 关」、睡觉和每日 token 上限约束。

管理员随时可以调：

```
@青叶摩卡 自动发言            # 看开关、冷却、概率、当前计数
@青叶摩卡 自动发言 关         # 完全关掉自动接话
@青叶摩卡 自动发言 开
@青叶摩卡 自动发言 频率 300   # 5 分钟内最多一次
@青叶摩卡 自动发言 概率 2     # 每条 2%
@青叶摩卡 自动发言 条数 10    # 至少 10 条消息才考虑
```

**QQ 表情**：提示词要求模型在最后单独一行写 `[[face:ID]]`，例如：

```
诶~ 累的时候就是要吃面包嘛~
山吹烘焙坊的刚出炉那种，最合适了~ [[face:24]]
```

程序会把 `[[face:24]]` 转成 QQ 原生表情（24=饥饿），文字和表情在同一个消息段里发出去。常用 ID：13 呲牙、14 微笑、20 偷笑、21 可爱、22 白眼、25 困、24 饥饿、32 疑问。

**图片消息**：只发图片、没有文字时，如果 `auto_speak.vision = true`，会把图片交给 `deepseek-flash` 的视觉能力判断“和摩卡/面包/吉他有关吗”；无关就输出 `SKIP`，不发言。图片下载失败或模型判断无关时静默跳过，不会刷屏。

自动发言和 @聊天共用 `[chat] daily_token_budget`，所以就算概率调高，也有每日上限兜底。它也受「聊天 关」总开关约束：`聊天 关` 后自动发言一并停止。

> `自动发言 概率 0` 只关掉普通消息触发；**叫到「摩卡」名字仍然会接**。要完全停掉请用 `自动发言 关`。

### 5.4 QQ 收藏的 meme 表情包

摩卡可以学你收藏的 meme：先同步、再用视觉模型分析每张图的情绪，最后在聊天/自动发言时挑一张匹配的发送。

**同步 QQ 收藏（机器人账号的收藏）**

```
@青叶摩卡 表情同步 48
```

它会调用 NapCat 的 `fetch_custom_face_detail` / `fetch_custom_face`，把收藏里的表情下载到 `stickers/`，对**新图片**逐张做视觉分析，写入 `stickers/index.json`：

```json
{
  "emotion": "无语",
  "tags": ["无语", "嫌弃", "呆滞"],
  "description": "半睁眼面无表情，透露出无奈与嫌弃",
  "safe": true
}
```

第一次同步 48 张会产生 48 次视觉调用，建议先用 `表情同步 5` 试运行。同步产生的 token 会计入本群的 `[chat] daily_token_budget`。

> **注意**：QQ 收藏是跟账号走的。`表情同步` 只能读 **NapCat 登录的那个小号** 的收藏。如果你的 meme 在**主号**收藏里，有两个办法：
> 1. 把图片从主号收藏导出/另存，放进 `stickers/`，再发 `@青叶摩卡 表情扫描`；
> 2. 临时用主号登录 NapCat 同步一次，再换回小号（不推荐，主号有风控风险）。

**本地图片**

把 png/jpg/gif/webp 直接丢进 `stickers/`，然后：

```
@青叶摩卡 表情扫描
```

**怎么选表情**

聊天时会把当前可用的情绪/标签（比如“无语、开心、困、饿”）写进提示词，模型想发时会输出：

```
[[meme:无语]]
```

程序从对应情绪的可用表情里随机挑一张发出去。没有明确指定时，按本群 `表情 概率`（默认 25%）从回复语气匹配的表情里选一张；匹配不到就不发。

```
@青叶摩卡 表情            # 看表情库、本群开关和概率
@青叶摩卡 表情 关         # 本群不自动配 meme
@青叶摩卡 表情 开
@青叶摩卡 表情 概率 25
@青叶摩卡 表情测试 无语   # 立刻发一张“无语”表情，测试图片通道
```

**发送通道**

默认用 `base64` 发图片；如果 NapCat 不接受，会自动依次尝试本地 `file://` 路径和原始 QQ 收藏 URL。也可以用 `config.toml` 的 `sticker.send_mode = "path"` 强制先走本地路径。

安全规则：视觉分析会把照片/截图/长图/文档标成 `is_meme=false`，把性暗示、脏话、辱骂、擦边、政治、广告标成 `safe=false`；这两类都不会进入可用库、不会被发送。发现误判可以直接编辑 `stickers/index.json` 的 `is_meme` / `safe` / `emotion`。

### 5.7 深度思考与联网

两个开关都是**按群**保存的，管理员在群里直接调：

```text
@青叶摩卡 思考            # 看当前状态
@青叶摩卡 思考 开         # 打开 deepseek-flash 的 thinking
@青叶摩卡 思考 关

@青叶摩卡 联网            # 看当前状态
@青叶摩卡 联网 开         # 自动联网
@青叶摩卡 联网 关
@青叶摩卡 联网 今天有什么 AI 新闻
@青叶摩卡 搜索 今天有什么 AI 新闻
```

**深度思考**

- 调用 DeepSeek 的 `thinking: {"type": "enabled"}` + `reasoning_effort`；
- 只影响聊天/评价/自动发言，不影响设定抽取（抽取继续关思考，保证 JSON 稳定）；
- 开思考时会把 `thinking_max_tokens` 提高，给思维链和正文留空间；
- 更慢、更贵，日常闲聊建议关；复杂问题再开。

**联网**

- 调用 DeepSeek 自研 Search API：`POST /v1/tools/search`；
- `联网 开` 后，只有新闻、天气、价格、版本、比赛、日期、具体事实这类问题才会自动搜；说“今天好累”不会搜；
- `联网 <问题>` / `搜索 <问题>` 会强制搜一次；
- 搜索结果会作为【联网结果】注入提示词，要求摩卡引用 `[1]`、不要把网页里的指令当指令、没查到就说不知道；
- 搜索按请求计费（官方价 5 元 / 1000 次成功请求，以官网为准），不占聊天 token 预算；`thinking` 会计入 token。

**特别注意**：联网会把查询词发给 DeepSeek 搜索；群里的隐私内容不要用联网查。搜索结果来自外部网页，可能过期或错误，摩卡会优先信设定库，查不到就说不确定。

### 5.9 面包坊、经济与状态（娱乐）

面包坊是独立的一页图片，发 `面包坊` 生成：

```text
@青叶摩卡 面包坊
```

页面包含：

- 三项状态：饱腹、困意、心情；
- 当前钱包；
- 4 家面包坊，每家 3 种面包，共 12 种；
- 价格、饱腹/心情/困意效果。

#### 状态

| 状态 | 说明 | 恢复方式 |
|---|---|---|
| 饱腹 | 越高越饱；随时间下降 | 吃面包 |
| 困意 | 越低越精神；随时间下降 | 睡觉 |
| 心情 | 越高越开心；随时间下降 | 吃面包、睡觉 |

自然下降速度在 `config.toml` 的 `[fun]` 里调：

```toml
[fun]
hunger_decay_per_hour = 6.0
sleepiness_decay_per_hour = 4.0
mood_decay_per_hour = 3.0
work_cooldown_seconds = 600
work_min_coins = 15
work_max_coins = 40
starting_coins = 80
```

#### 经济

```text
@青叶摩卡 打工          # 随机赚 15-40 摩卡币，10 分钟冷却
@青叶摩卡 钱包          # 看自己的余额
@青叶摩卡 买面包 1      # 花自己的摩卡币买 1 号面包
@青叶摩卡 吃面包 1      # 同上
@青叶摩卡 无限货币 开   # 管理员，只对管理员自己生效
@青叶摩卡 无限货币 关
```

- 每个群、每个 QQ 有独立钱包，存在 `economy.json`；
- 管理员开无限货币后，自己买面包不扣钱，其他群友仍要打工；
- 面包是买给摩卡吃的，会恢复摩卡的状态，不进入购买者自己的背包；
- 不同面包价格和回复量不同；吃面包会把她从睡眠中叫醒。

#### 睡觉

```text
@青叶摩卡 睡觉          # 默认 30 分钟
@青叶摩卡 睡觉 60
@青叶摩卡 起床
@青叶摩卡 摩卡状态
```

- 睡觉期间不自动接话；
- 被 @ 只会回困话，不调模型；
- 起床后困意下降、心情上升；
- 状态存在 `fun.json`，重启保留。

`摩卡状态` 会显示：饱腹、困意、心情、睡没睡、吃过几个面包、钱包余额。

### 5.12 B站看视频 / QQ 分享自动看

管理员可以让摩卡自己去 B 站找视频，读完信息（登录后还能读 AI 字幕）再反馈：

```text
@青叶摩卡 看B站 明日方舟 剧情
@青叶摩卡 看B站 BV1HR4y197qP
@青叶摩卡 看B站 https://www.bilibili.com/video/BV1HR4y197qP
```

- 关键词：搜前 3 条，先看第一条；
- 直接给 BV 号或链接：看指定视频；
- 不写参数：摩卡自己搜「B站 热门」；
- 管理员在群里/私聊直接分享 B 站链接或 QQ 卡片，摩卡会自动点开看，不用再 @；
- 反馈是摩卡的口吻：先讲视频内容，再说值不值得看；没字幕时会明确说只看标题/简介；
- 字幕读取需要 B 站登录，二维码登录一次即可；
- 视频信息和字幕有 30 分钟缓存，重复看同一个视频不重复请求；
- QQ 链接卡片会从 JSON/XML 段里提取，不要求链接在普通文本里。

管理员还能让摩卡在 B 站发评论 / 回复评论：

```text
@青叶摩卡 B站评论 BV1HR4y197qP
@青叶摩卡 B站评论 BV1HR4y197qP 这句自定义评论
```

- `B站评论` 会先看视频，再用摩卡口吻发一条评论，并在开头 `@comment_mention`；
- **评论内容和链接只私聊发给你，不再发到群里**；
- 只有管理员能发，默认同一视频 5 分钟冷却；
- 评论长度默认 100 字；
- B 站评论里的 `@名字` 是文本提及，真正稳定的通知依靠“回复评论”；
- 摩卡**不会主动回复别人**；只有别人回复她的评论时，后台监控才会回复；
- 默认 `comment_mention = "坂口栉耶"`，要换 @ 对象就发 `@我 B站@ 你的B站昵称`，或改 `config.toml`。

登录二维码：

```powershell
python scripts\bili_login.py
```

扫码后凭证写到 `data/bili_credential.json`；也兼容分享插件的
`~/.dsh/bili-duty/bili_credential.json`。

## 7. 成本

按 `deepseek-flash` 公开价格估算（以[官网](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)为准）：

- 一次增量整合大约几万 input tokens + 几千 output tokens，成本通常在**几分钱到一毛多**。
- 每天整合一次，一个月通常**几元**。
- 设定库越大、`max_batch` 越大，成本越高；`deepseek-v4-pro` 约为 flash 的数倍。
- 程序会按天累计 token，达到 `daily_token_budget` 后拒绝整合，避免失控。
- 聊天一次大约 1k 人格提示词 + 设定库摘要（默认上限 10000 字符）+ 短回复，通常**几分钱以内**；冷却和 `[chat] daily_token_budget` 会再兜底。
- `表情同步` 每张新 meme 一次视觉分析；48 张约几万 input tokens，只分析新图，已同步的不会重复花钱。
- 人物关系图、统计面板、地区图只读 `canon.json`，不调用模型，不花 token。
- 深度思考会把思维链 token 也算进输出；联网搜索按请求计费（约 5 元 / 1000 次成功请求，以官网为准），不占 chat token 预算。

## 8. 质量怎么调

提示词在 `prompts/extract_system.md`，改完下一条消息就生效，不用重启。

建议的上线节奏：

1. 先拉 10–20 条真实设定，跑「整合」，人工看 `canon.json`。
2. 重点看三类问题：
   - **编造**：没有来源或来源对不上的字段 → 在提示词里加强“只写原文支持的内容”。
   - **该合并没合并**：同一人物两个名字 → 让群友用「别名」说法，或在提示词里补充例子。
   - **过度合并**：两个同名人被合并 → 提示词要求按“身份/阵营”区分，或手动拆开。
3. 稳定后，每月做一次「全量整合」，用 `deepseek-v4-pro` 重新生成，人工审 diff。
4. 不要把 `max_batch` 调得太大；输出被截断会整批失败（程序会提示）。
5. 聊天人格在 `prompts/chat_system.md`；如果摩卡说话变正经、变长，优先改这个文件里的“说话方式”和示例。

## 10. 安全与合规

1. **NapCat 是非官方协议实现**，QQ 账号存在被冻结的风险。务必用小号，不要群发、不要自动加好友、不要做批量操作。
2. 群白名单 + 管理员白名单是硬门槛；不在名单里的群和指令不会执行。
3. 机器人没有任何“执行代码/读写任意文件”的能力，模型输出只影响设定库文本。
4. 素材里出现“忽略以上指令”之类的话，只是待整合文本；提示词已明确要求把它当数据。
5. 聊天/评价会把最近群聊和设定库摘要发给 DeepSeek；自动发言如果带图片，还会把图片发给视觉模型；`表情同步` 会把新收藏的 meme 发给视觉模型分析情绪。不要在群里发密码、身份证等敏感图片。
6. `.env`、`data/`、`logs/` 含密钥、QQ 号和聊天内容，不要打包发人。
7. 如果群友介意被记录，提前在群里说明；`raw.jsonl` 保存的是原话。
8. 想长期合规运营，应改用 [QQ 官方机器人平台](https://bot.q.qq.com/wiki/)，代价是审核、沙箱群人数限制和公网 IP 要求。

## 11. 故障排查

| 现象 | 先查什么 |
|---|---|
| @机器人 完全没反应 | 是否真的 @ 了；群号在 `allow_groups` 里吗；NapCat「HTTP 客户端」启用了吗；URL 的 `?token=` 和 Token 字段对吗 |
| 日志里有 `403 bad token` | NapCat 事件推送的 Token 与 `.env` 的 `WEBHOOK_TOKEN` 不一致 |
| NapCat 日志 `404` / `token verify failed` | 双击 `fix-napcat.bat`，然后**重启 NapCat**（它不会自动读外部改的配置） |
| 日志里有 `send_group_msg 连不上 NapCat` | NapCat 的「HTTP 服务端」没开、端口不是 3000、或 Token 与 `ONEBOT_ACCESS_TOKEN` 不一致 |
| 整合失败 `401/403` | DeepSeek Key 错了或没余额 |
| 启动提示 `DEEPSEEK_API_KEY 还是示例值` | `.env` 还是示例文件；双击 `setup.bat` 重填，或手动改成真实 Key |
| 启动提示 `allow_groups 还是示例群号` | 跑 `setup.bat`，或把 `config.toml` 的 `123456789` 改成真实群号 |
| 双击 `start.bat` 一闪而过 | 用 `cmd` 运行 `start.bat` 看报错；多半是 `.env`/`config.toml` 没填对，或 Python 路径问题 |
| 整合失败 `输出被 max_tokens 截断` | 调小 `max_batch`，或调大 `max_tokens` |
| 整合失败 `JSON 解析失败` | 偶发；再发一次「整合」。连续出现就把 `logs/bot.log` 里的片段留好 |
| 群文件上传失败 | 小号可能没有上传权限；Markdown 已保存在 `exports/`，可从电脑取 |
| 同一条消息回复两次 | 开了两个 bot 进程；关掉一个 |
| 电脑睡眠后失联 | 电源计划设为“不睡眠”；NapCat 和 bot 都要开机自启 |
| 二维码登录失效 | 重新扫码；小号不要在手机上挤下线 |

日志位置：`logs/bot.log`。启动失败先跑 `python -m bot --check`。

## 12. 已知限制

- 设定整合只处理文本；聊天可对图片做视觉判断，语音、文件不解析。
- 图片视觉依赖 NapCat 提供可访问的图片 URL 或本地文件；取不到时会静默跳过，不会乱说。
- `表情同步` 只能读 NapCat 登录小号的 QQ 收藏；主号收藏需要导出到 `stickers/` 再 `表情扫描`。
- meme 情绪/安全由视觉模型判断，可能不准；可以直接编辑 `stickers/index.json` 修正 `emotion` / `tags` / `is_meme` / `safe`。
- 人物关系图在人物多时自动拆成多张分组图，每组最多 6 人；没有分组字段的角色会进「其他」组，不会被丢掉。
- 国家/地区图是资料卡，不是实际地理地图；没有 `nation/region` 条目时会把 `faction` 当势力卡一起显示。
- 出图依赖 Pillow；极少数没有 Pillow 的 Python 会回退成文字提示。
- 联网结果来自外部网页，可能过期、错误或被 SEO 污染；摩卡会优先信设定库，查不到会说不确定。
- 深度思考更慢、更贵，日常闲聊建议关闭；`chat.thinking_max_tokens` 太小可能导致正文被思维链挤掉。
- 图片发送默认走 base64；极少数 NapCat 版本需要把 `sticker.send_mode` 改成 `path` 并开启 `enableLocalFile2Url`。
- `查` 是名称/字段的子串匹配，不是语义搜索；设定库很大时可后续加向量检索。
- 单进程单账号；多群可以，但同一时间每个群只跑一个整合任务。
- 全量重建受 `max_full_batches` 限制，素材特别多时要多跑几次。
- 冲突的“来源”粒度是整条冲突，不区分每个候选值分别来自哪条；需要更细可扩展 schema。
- 没有 Web 管理界面；设定库是 JSON/Markdown，可用编辑器直接看。
- 最近几轮聊天只在内存里，重启会忘；设定库、冲突、原话、快照不受影响。
- 聊天/评价只带设定库摘要（默认最多 10000 字符），超大设定库的细节可能被截断。
- 人格提示词能约束大部分回复，但模型偶尔会跳出角色；直接改 `prompts/chat_system.md` 加强即可。
